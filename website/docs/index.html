01 / ORIENTATION

What Open Forensic does

Open Forensic is a local-first financial review workspace. It normalizes bank statement rows, screens them against rules you choose, shows the calculation behind each potential discrepancy, and keeps your decisions with the evidence. It can prepare a letter and export a schedule for a follow-up review.

A screening tool, not a finding of liability

A flag means the configured model and the available statement differ. Check the source records, account agreement, tariffs, value dates, historical rates, exemptions, and applicable law before making a claim.

01Local by default

Statements and review state stay in the browser or desktop profile.

02Transparent checks

Findings retain their rule inputs, calculations, and source transaction.

03Your decision

Confirm, exclude, or reopen a signal before preparing output.

03 / FIRST REVIEW

Your first review, in five steps

The initial workspace contains clearly labeled synthetic transactions. Explore it freely. Your first real import replaces the demo.

  1. 01

    Import a statement

    Choose Import, select CSV, XLSX, or MT940, and inspect the preview before committing it.

  2. 02

    Confirm your rules

    Open Audit rules. Set the rate, tax, date basis, window, and tolerance that apply to your account. Confirm the profile to run the checks.

  3. 03

    Read the evidence

    Open Evidence ledger. Compare the transaction, rule assumptions, explanation, and calculation with your source statement.

  4. 04

    Record a decision

    Mark supported items Confirmed, dismiss irrelevant ones as Excluded, and reopen them if new evidence changes your view.

  5. 05

    Prepare the output

    Use Export console for CSV or a PDF draft. In AI assistant, fill a request from confirmed findings and save its PDF to the workspace.

04 / SOURCE FILES

Prepare a statement

For CSV or XLSX, use a bank-provided export where possible. The file should have a date, description, and either a signed amount or debit and credit columns. Balance, reference, account, currency, and direction columns are helpful but optional. The import preview is where you confirm the mapping.

FieldWhat the importer needsExample
DateA valid transaction or posting date12/10/2026
DescriptionA readable transaction narrativeService charge
AmountA signed amount, or separate debit/credit columns-24.00
OptionalReference, account, balance, currency, directionABC-1024 · USD

Choose day-first or month-first when dates are ambiguous. Monetary values should have at most two decimal places. Values such as 1,234 and 1.234 with a single ambiguous separator are excluded so you can correct them in the source file. Keep one currency per workspace; a statement containing mixed currencies must be split before import.

Keep the source file

Open Forensic parses the statement locally but does not retain the raw file. Keep your original export separately so you can check every row and calculation later.

05 / BRING IN THE DATA

Import with a visible preview

Select Import from the top bar or the assistant. For XLSX, choose the relevant sheet. For CSV and XLSX, map the columns to date, description, amount or debit/credit, and any optional fields. The assistant can suggest a mapping in the desktop app when connected, but you must review it before import.

  1. Review the normalized preview. Check debit and credit signs, descriptions, currency, and dates against the source.
  2. Read every warning. Excluded CSV/XLSX rows and MT940 source warnings are shown for acknowledgment before import. Unsupported MT940 precision may cause a row to be skipped.
  3. Commit only when it matches. A real import replaces the synthetic demo. Importing a different currency into an existing real workspace requires a new workspace.

Standard MT940 files are parsed directly; the importer also checks opening and closing balance information when present. Scanned PDFs and bank-specific PDF layouts are outside this release.

06 / YOUR ASSUMPTIONS

Configure audit rules

The rules are screening assumptions, not legal or statutory defaults. Confirm a profile that fits the account and period before interpreting a finding. Reapply the rules as evidence changes; review decisions stay attached to stable transaction IDs where the same transaction remains.

SettingEffectCheck before using
Annual rate + marginSets modeled interest on a negative running balance.Agreement, rate changes, effective dates.
Day basis + methodUses 360 or 365 days and simple or compound modeling.Bank method and value-date practice.
Tax / levy rateApplies the configured percentage to linked debits.Applicable tax basis and exemptions.
Minimum + capBounds modeled tax / levy where configured.Current tariff and account terms.
Exemption keywordsExcludes matching descriptions from the modeled tax check.Whether the exemption really applies.
Duplicate-fee windowDefines how close repeated fee-like entries must be.Legitimate recurring charges.
Discrepancy toleranceFilters differences below the chosen threshold.Rounding and materiality for this review.
Start with evidence, not defaults

Open Forensic does not infer historical rates, value dates, contracts, or tariff changes. Document the source for each setting you use and revisit it when the statement period changes.

07 / EVIDENCE REVIEW

Understand and decide on findings

Each finding links back to a transaction and shows an explanation, modeled expectation, actual charge, potential difference, and calculation. The Overview summarizes; the Evidence ledger contains the full review.

01

Interest

Models daily interest on negative running balances between statement dates and compares it with an interest debit. Check value dates and historic rates separately.

02

Tax or levy

Links a tax entry to a preceding debit with the same reference, then applies the configured percentage, minimum, cap, and exemptions. Unlinked rows are not flagged.

03

Duplicate fee

Looks for the same normalized fee description and amount within your date window. A repeated legitimate charge can still match.

04

Overdraft penalty

Highlights an overdraft-related charge when the reconstructed balance immediately before it was positive. Verify bank balance and timing rules.

Needs reviewScreening signal awaiting your decision.
ConfirmedSupported for your follow-up review; still not a proven claim.
ExcludedSet aside after review; can be reopened later.
08 / OPTIONAL AI

Use the guided assistant

The assistant organizes import, interpretation, drafting, and saved documents. The browser build provides the guided local workflow. The desktop app adds an optional AI connection for eligible users.

01

Connect, if you choose

In the desktop app, choose Continue with ChatGPT or use an OpenAI API key for the current session. ChatGPT sign-in is an experimental preview for eligible accounts and has not been verified with a real account in this release. The API key is separate from a ChatGPT plan.

02

Ask for a specific task

Use AI to suggest a column map, explain selected findings, or refine a request letter. You trigger each request explicitly and review the answer against the underlying record.

03

Control the data shared

Mapping sends selected sample rows; interpretation sends up to 25 finding summaries and rule settings; drafting sends recipient details and up to 25 confirmed findings. No background statement-file upload or automatic bank submission is connected.

AI output is a draft

Check names, dates, amounts, calculations, and any factual statement before saving or sharing a letter. The local fill action includes all confirmed findings even when AI refinement is limited to 25.

See OpenAI’s local sign-in guidance ↗ and preview limits ↗ for account eligibility and usage requirements.

09 / TAKE IT FORWARD

Documents and exports

In Export console, export confirmed findings or the full transaction ledger as CSV, with optional calculation notes. Download an A4 PDF review draft and edit or copy the bank communication text. These outputs are generated locally.

In AI assistant → Fill a review request, enter the bank, optional contact, and your name. Select Fill from confirmed findings, edit the letter, then choose Save PDF to workspace or Download filled letter PDF. Saved PDFs appear under Saved documents and remain available after reload on that device.

“Save to workspace” means local storage

Generated PDFs are stored in this browser or desktop profile. The app does not upload them to a bank, email them, or sync them to a server. Starting a new workspace or restoring the demo permanently deletes the current workspace’s saved PDFs after confirmation.

Keep a downloaded copy of every document you need outside the app. Clearing browser data or deleting the desktop profile also removes locally stored documents.

10 / DATA HANDLING

Know where your data lives

Statement files

Read and parsed on the device. The raw source file is not retained.

Transactions and decisions

Stored in IndexedDB within the current browser or desktop profile.

Saved review PDFs

Stored locally with the workspace in IndexedDB; downloaded files remain wherever you save them.

AI requests

Only the selected rows, findings, settings, or recipient details for an action you initiate are sent to OpenAI after a desktop connection.

Credentials

Desktop ChatGPT credentials use operating-system protected storage when available; otherwise tokens stay in memory for that session. An API key remains in memory for its session.

There is no statement-upload API, server database, or analytics in this build. IndexedDB is not encrypted at the application level. Use a trusted device and operating-system account, and download copies of important output before clearing local data.

11 / SCOPE

Formats and limits

Supported

  • CSV and XLSX with reviewed column mapping
  • Standard MT940 (.mt940 or .sta)
  • One currency per workspace; multiple accounts in that currency
  • Local CSV and PDF output
  • Desktop AI connection preview

Outside this release

  • Scanned PDFs, OCR, or universal bank PDF import
  • Automatic bank portal upload or email sending
  • Server sync or application-level encrypted storage
  • Automatic inference of historical rates or value dates
  • Verified offline operation across every browser

Amount parsing supports no more than two decimal places. MT940 entries with finer unsupported precision are skipped with a warning. The app surfaces import warnings and exclusions; reconcile row counts against the source before relying on the review.

12 / HELP

Troubleshooting

The import shows excluded rows. What should I do?+

Open the warning list. Check missing or invalid dates, ambiguous amount punctuation, both debit and credit values on one row, unsupported precision, and incorrect column mapping. Correct the source export and preview it again before importing.

My CSV dates look reversed.+

Choose day-first or month-first in the import preview. Compare several rows with the original statement, especially dates where both numbers are 12 or less.

I cannot mix currencies in one workspace.+

Split the source by currency and start a new workspace for each currency. The app prevents summing different currencies without a conversion basis.

No findings appear after import.+

Open Audit rules and confirm the profile. Check the statement period, amounts, tolerance, and whether any rule actually applies. No active findings under a profile is not proof that every bank charge is correct.

The Install app button does not show a prompt.+

Use the browser menu option shown by the button. The browser workspace must be served over HTTPS in a supported browser. A regular browser tab remains usable.

ChatGPT sign-in or an AI request fails.+

Check that you are using the desktop build, have an eligible account, and can reach OpenAI. ChatGPT plan usage is a preview and may be unavailable or limited. The desktop app offers a separate API-key option. Review OpenAI’s current preview limits ↗.

Where did my saved PDF go?+

Open AI assistant → Saved documents on the same browser or desktop profile. A new workspace, restored demo, cleared browser storage, or deleted profile removes local saved PDFs. Check your Downloads folder for copies you exported.

The result differs from the bank’s calculation.+

Compare the source rows and all profile assumptions with the tariff, contract, effective rate, value dates, and bank calculation. Open Forensic models only what the supplied data and configured rules support.

13 / FOR DEPLOYERS

Self-hosting the website and browser app

The marketing website is a static directory at website/. The browser app is a separate static export. They can share a server but should use separate origins or virtual hosts: the current app export and service worker expect the root path of their origin, not a nested /app/ path.

BUILD THE BROWSER APP
pnpm install --frozen-lockfile
pnpm export:app
  1. Serve website/ as the product site, including docs/index.html and its assets.
  2. Serve generated out/ at the browser app origin root over HTTPS. Keep service-worker and asset paths intact.
  3. Replace the product site’s browser-app placeholder with the new app URL only after both origins are reachable.
  4. Check the Overview, /agent/, statement import, and a saved PDF on the live origin before announcing it.

No application API or database is required for the browser export. AI sign-in remains part of the desktop wrapper. See the MIT source repository ↗ for build scripts and tests.
